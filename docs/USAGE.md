# bnguclient 使用方法

本指南对应台架测试版默认的 FPS 界面。真实 MQTT TCP 与 UDP H.265 均由 Tauri/Rust 桌面后端接收；浏览器中的 `?demo=1` 只用于检查页面和前端解码链路。

## 1. 启动并识别数据来源

从源码运行：在仓库根目录执行 `npm ci`，再执行 `npm run tauri dev`。Windows 已有 release 构建可双击 `Start-bnguclient.cmd`；Linux 安装和压缩包运行方法见 [Linux 指南](LINUX.md)。启动后左上角会显示当前机器人编号及来源：`OFFLINE`、`本地演示`、`本机测试链路` 或实时连接状态。**不要把“本地演示”截图当成裁判系统连通证据。**

默认视野以图传为中心。按 `Esc` 打开菜单，再按一次返回；菜单打开时键鼠采集停止，图传和遥测接收继续。`Ctrl+1…5` 打开对应菜单页，`F10` 隐藏部分侧边 HUD，桌面版 `F11` 切换全屏。返回视野后不会自动重新启用控制。

## 2. 连接裁判系统

按 `Esc` → **设置** → **裁判系统连接**：

1. 填 MQTT 主机名或 IP，不要加 `mqtt://`；填端口和机器人 ID。默认值来自仓库固定的 2026 协议基准，现场以队伍当前网络配置为准。
2. 点击“保存配置”，再点击“连接裁判系统”。
3. 左上角应显示实时链路；进入 **遥测** 查看接收速率、消息总数、最新数据年龄和会话日志。
4. 进入 **协议** 查看 `RobotStaticStatus`、`RobotDynamicStatus`、`RobotModuleStatus` 等主题的解码对象。收到消息但视野仍为“等待血量”时，先看动态消息是否真的包含 `currentHealth` 字段。

连接成功只说明 MQTT 会话建立；收到且成功解码消息，才能说明数据链通。状态超过阈值会显示过期。HP 的 `0` 是有效值；从未收到 HP 显示 `—`，停止收到 HP 超过 3 秒显示“血量数据已过期”。

## 3. 启动图传

仍在 **设置** 中填 UDP 监听端口和发送端 IP 过滤。过滤字段可留空；若填写，它必须与实际发包源地址一致。点击“启动视频”，再按 `Esc` 回到视野。画面应出现实时图像，右下角显示 FPS、解码队列和解码耗时。无画面时先核对 UDP 端口、发包源 IP、H.265 数据以及系统防火墙；“正在监听”本身不代表已经收到完整视频帧。

## 4. 查看超电相关状态

- **视野左下角**：`底盘能量` 来自 `RobotDynamicStatus.currentChassisEnergy`，单位按当前客户端显示为 J。它不是电容端电压。
- **Esc → 协议**：查看 `RobotDynamicStatus.currentChassisEnergy`、`currentBufferEnergy` 的原始解码值和更新时间。
- **Esc → 协议 / 模块状态**：查看 `RobotModuleStatus.capacitor` 是否出现、是否变化。模块状态字段不提供电压曲线。
- **Esc → 接口**：查看是否收到 `CustomByteBlock`；字节检查器可以离线验证双方约定的布局。当前内置步兵 XML 的 `infantry`、`infantry_ois` 不是经电控确认的电容电压字段。

如果要显示电池电压、电容电压、电流或输出功率，需要电控端确定发送链路和字节布局，并提供一组**原始字节 + 实测物理量**对照，之后再改客户端解析和 UI。底盘源码中的 CAN `0x212` 字段不会自动进入 MQTT。

## 5. 控制和发送指令

本轮接线测试建议先保持“键鼠控制未启用”，只接收状态。主视野的“启用控制”按钮只有真实连接、机器人身份匹配和新鲜状态满足条件时才可用。按 Esc、切页、窗口失焦或状态过期会停止采集并尽力提交中立帧；网络断开时中立帧可能无法到达，设备端必须独立验证失联保护。

**协议**页的上行指令需要手动检查参数并再次确认发送。界面显示“已提交”只表示请求通过客户端链路，不等于服务器接受或机器人执行；看服务器状态回读和实物结果。测试超电状态的第一轮无需发送任何上行指令。

## 6. 留存证据

按 Esc → **遥测** →“导出 JSON”，保存会话日志、解码后的最近消息与趋势；在 **协议** 页记录关键消息字段。视频可用截图按钮保存当前帧。请按 [测试记录模板](TEST_RECORD.md) 写清客户端提交、裁判服务器版本、机器人 ID、网络地址、时间、所见值和电控端同时测得的值。导出文件可能包含现场地址和状态，按队内方式保存。
