## 电控遥测

入口为 MQTT `CustomByteBlock`，外层 `bytes data = 1` 先经过 Protobuf 解码。内部由 `RobotConfig.yaml` 指定机器人类型，再按 `CustomByteBlockConfigs/<type>.xml` 解析。接口页保存的 JSON 布局优先于内置 XML，并保存在参考版 WebView 的独立 localStorage。

默认步兵模式 0：

| offset | 长度 | 字段 | 类型 |
| ---: | ---: | --- | --- |
| 0 | 1 | mode=0 | uint8 |
| 1 | 4 | infantry | IEEE754 float，小端 |
| 5 | 1 | infantry_ois | int8，有符号 |
| 6…149 | 144 | 填充 | 当前布局不读取 |

`00 00 00 48 41 FD` 再补零至 150 字节，解析为 `infantry=12.5`、`infantry_ois=-3`。名称沿用 XML，**没有擅自把它解释为某个实际电控状态量**。

模式 1 使用伴随字段与 128 字节 ImageBlock。解析器检查 offset、长度、端序、命令类型、块索引；Store 以有界 FIFO 保留图片块，重组器最多保留四张未完成图片，每张最多 4096 块，10 秒无更新清除。PNG/JPEG 可在接口页预览。图片 ID 复用、发送端重传与时序仍需和电控共同验证。

JSON 中的 `version` 是本地布局版本，**现有 150 字节队伍帧没有线上版本字段**。它不能自动证明发件端版本一致。双方升级时须一起约定版本协商/魔数/长度或新主题，不能只改 UI 里的数字。

## 电控指令

上行采用 `CustomControl { data: Uint8Array }`，最多 30 字节。参考版提供类型/大小验证、频率限制和手动指令工作台；没有编造底盘、云台或开火自定义编号。实际接入前由电控确认每一字段的 offset、类型、单位、端序、命令枚举、失联超时与中立值。

键鼠采用官方 `KeyboardMouseControl`。本地采集退出、切页、窗口失焦和过期状态会停止主动操作，尽力发送释放帧。网络断开时释放帧可能无法到达，因此**设备端必须独立处理控制超时**；客户端不把 IPC 提交成功当作机械动作确认。

## 视频与其他设备

图传保留原 Rust `udp_bridge`、分片重组和 H.265 解码器。前端不重新实现 HEVC，使用后端 MJPEG 输出；本地压测记录不是比赛设备性能保证。来源过滤、端口和 JPEG 质量可设置。

外部 AI 服务、相机标定、串口/CAN、专用电控命令、实际场地地图属于设备接入边界。旧工作台接口保留，主界面未接设备就不会标成在线。示意地图默认 28×15 坐标范围只是可视化范围，**没有假装完成赛场标定**。
