# 裁判系统与超电链路台架测试指南

目标是证明真实设备把哪些状态送到了裁判系统、裁判系统再把哪些状态送到了 bnguclient。按下面顺序测试，每一步只在前一步证据成立后继续。第一轮只收数据，不启用键鼠控制，也不发送裁判交互指令。

## 测试前记录

在 [记录模板](TEST_RECORD.md) 中填好客户端提交号、测试时间、机器人 ID、裁判服务器地址与端口、电脑有线网卡地址、UDP 监听端口、电控固件提交号以及超电模块型号。确认电控人员知道现场的串口/CAN 接线和测量位置。若现场协议或网段与仓库默认值不同，以现场配置为准。

先在本机用 Mock 跑通客户端软件链路：仓库根目录 `npm ci`、`npm run tauri dev`；另开终端进入 `tools/rm2026-mock-server`，执行 `npm ci` 和 `npm run dev -- --mqtt-port 1884 --udp-port 3335`。客户端设置 MQTT `127.0.0.1:1884`、机器人 ID `3`，UDP `3335`、来源 `127.0.0.1`。能看到动态 HP 和测试图后，记录为“本机软件通过”，**不要填成实机通过**。

## 实机第一轮：只接收 MQTT

1. 断开 Mock。连接电脑与现场裁判系统网络，启动桌面版。按 Esc → 设置，填现场 MQTT 主机、端口和本机机器人 ID；先不要启动控制。
2. 点击连接。确认左上角不再显示 `OFFLINE` 或 `本地演示`。进入 **遥测**，观察接收总数和速率是否增加，并记录 30 秒内是否出现解析失败。
3. 进入 **协议**，分别记录 `RobotStaticStatus.robotId`、`maxHealth`、`RobotDynamicStatus.currentHealth`、`currentChassisEnergy`、`currentBufferEnergy`、`RobotModuleStatus.capacitor`。某字段没有出现时写“缺失”，不要把它记成 0。留一份 JSON 导出。
4. 返回操作视野，确认机器人编号与现场一致。观察 HP：未收到时 `—`；实际 0 时显示 `0`；停止收到 HP 超过 3 秒显示“血量数据已过期”。恢复数据后应回到正常显示。

若连接成功但无消息，先让服务器侧确认该 clientID、订阅主题和发布记录；若协议页已有消息但字段为空，核对服务器实际 Protobuf 字段与仓库 `UDP-MQTT Server/proto/messages.proto`。不要只凭 UI 的连接灯判断数据已通。

## 实机第二轮：核对超电相关值

让电控人员在同一时刻记录超电模块或 CAN `0x212` 的电容电压、电池电压、电流、输出功率，以及设备当时的工作状态。客户端同步记录：

| 客户端可见项 | 来源 | 能证明什么 |
| --- | --- | --- |
| 底盘能量 | `RobotDynamicStatus.currentChassisEnergy` | 裁判 MQTT 提供了该能量字段；须与现场定义核对含义。 |
| 缓冲能量 | `RobotDynamicStatus.currentBufferEnergy` | 裁判 MQTT 提供了缓冲能量字段。 |
| 电容模块 | `RobotModuleStatus.capacitor` | 收到模块状态码；它不是电压。 |
| CustomByteBlock | `CustomByteBlock.data` | 收到一段自定义字节；需要双方字节表才能命名物理量。 |

**不要把底盘能量或模块状态当作超电端电压。**在已查看的电控工程里，CAN `0x212` 可解析电容电压，但尚未发现把该量打包进本客户端 `CustomByteBlock` 的发送路径。若这次现场设备已经新增发送代码，请保存固件提交号、topic、原始 payload、一份字节布局（offset、长度、类型、端序、单位）和同时刻仪表/CAN 值；确认后再新增解析与 UI 字段。UI 会话 JSON 主要保存解码结果，不保证包含原始二进制 payload；原始包应从服务器日志或抓包另存。

## 可选：UDP 图传

确认 MQTT 状态后再测图传。设置正确的本地 UDP 监听端口和发送端 IP 过滤，点击“启动视频”。记录是否出现画面、FPS、解码队列、丢帧数及断流提示。若只有“等待视频帧”，分别验证 UDP 包是否到达、8 字节分片头格式、H.265 码流完整性及源地址过滤。图传问题与 MQTT 状态问题分开记录。

## 收尾与问题定位

测试结束，先按 Esc 确认控制未启用，再断开 MQTT、停止视频，保存会话 JSON 和填写的记录。若后续要进行键鼠或上行指令测试，应作为独立测试，由电控确认模式、机械运动范围和设备端失联保护后再开展。

| 现象 | 优先检查 |
| --- | --- |
| MQTT 未连接 | 有线网络、服务器 IP/端口、clientID、服务是否在监听。 |
| 已连接但消息总数不增加 | 服务器发布和订阅主题、机器人身份。 |
| 有消息但解析失败增加 | topic 对应的 Protobuf 类型、字段版本、保存的原始 payload。 |
| HP 正常但超电电压没有 | 电压是否被电控发送到了 MQTT；标准能量字段不能代替它。 |
| HP 显示 0 | 协议页确认是否真的收到显式 `currentHealth: 0`。 |
| HP 显示过期 | 检查动态状态发布是否停止、是否只有其他 topic 仍在更新。 |
| 视频无画面 | UDP 包、端口、来源过滤、分片完整性、解码日志。 |

本指南使用仓库现有协议和已核对的电控源码作为测试假设。实机结果以本次记录和现场抓包为准。
